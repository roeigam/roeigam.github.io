v0.6.0

Guest Access · Trip Cover Image Security — new · Navigation Shell 1.0.0 → 1.1.0

Opens the Library to anonymous visitors (browse freely, sign-in only prompted on actual write actions), restricts trip cover images to an explicit host allowlist instead of any URL, and closes two real deployment gaps found while auditing for launch. Also finalizes two decisions previously left open: countries in scope (Iceland + Germany, both real, permanently), and auth strategy (accounts required for trip creation, permanently — not a deferral).

Added
  • Guest Access — /library and its sub-routes opened to anonymous visitors, previously redirected to login before browsing at all. Attempting a write action (save, add to day) while signed out now opens a sign-in prompt instead of silently failing.
  • Trip Cover Image Security — the cover image field was a free-text URL with no host restriction. Added an explicit allowlist enforced server-side on create/update, plus client-side for immediate feedback; the image-optimizer config now generates from the same allowlist instead of a separately hardcoded one, so the two can't drift.
  • A pre-launch checklist tracking everything still needing manual action before going live — credential hygiene, production OAuth redirect URI, host choice, repo visibility, and a parked note on anonymous shareable trip links.
Fixed — both deploy-breaking
  • No postinstall script, so a fresh install on a deploy host would never generate the Prisma client.
  • The Report table (added in v0.5.0) only existed via a direct schema push, no migration file — a clean migration deploy against a fresh database would have silently skipped it. Added the missing migration, marked applied against the existing database with no data touched.
  • Navigation Shell (1.1.0) — the marketing nav overlapped the top bar and hid "My Trips" for logged-in users on the home page. Simplified to a lightweight marketing-only bar.
package.jsonthe actual one-line fix
"scripts": {
  "postinstall": "prisma generate"
}
Data & docs
  • Removed a small number of leftover test entries from the public library, confirmed via direct query to have zero references elsewhere first.
  • Corrected a factual error in the planning doc: one country was assumed to have only a few leftover test places — verified directly against the live database instead, it has 150 real, deliberately-built places. Nothing gets pruned.
Known gaps
  • The Report migration gap is closed, but an unrelated migration-history drift noted in v0.5.0 is still unresolved.
  • The country dropdown still lists dozens of world countries with no library content behind them — tracked in the pre-launch checklist, not urgent while usage is internal-only.

v0.5.0

Reporting · Navigation Shell — new

Closes the last missing piece of the original MVP core loop — the flag/report button — and replaces the sidebar with a top navigation bar. Also fixes a bug that would have silently broken every image added by v0.3.0's data work.

Added
  • Reporting — a report model with reason categories (wrong hours, permanently closed, not worth it, other), a public endpoint requiring no login, and a "Something wrong?" dialog on place detail views. Read directly from the database for now — no admin UI yet, matching MVP scope.
  • Navigation Shell — desktop sidebar removed; navigation now lives in the top bar. Mobile's bottom nav untouched.
Fixed
  • The image optimizer only whitelisted one image host — every photo added by v0.3.0's data work would have failed to render. Added the two other real sources in use.
  • Two fixed-position elements in the day builder had left-offsets calibrated to dodge the now-removed sidebar. Adjusted both.
Security
  • Local environment config files had been tracked in version control. Untracked them and corrected .gitignore. Full credential rotation tracked separately as pre-launch hardening.
  • Rewrote git history to remove an incorrect co-author attribution on one commit.
Known gaps
  • The Report model was applied via direct schema push — the standard migration path detected pre-existing, unrelated drift and wanted to reset the entire database, which was refused. Zero data loss, but no migration file exists for this table yet.

v0.4.0

MVP Feature Flags — new

Reduces the app's surface down to the confirmed MVP core loop (browse → add to day → build → see a verdict), after an internal audit found most of the MVP already works but is surrounded by extra features built alongside it (a marketplace, a multi-country explore picker, a live on-trip mode, a route optimizer). Nothing is deleted — every hidden surface sits behind one feature-flag file and can be restored with a one-line change.

Added
  • MVP Feature Flags — a single source of truth for which non-core surfaces are hidden. Every hide this release is a conditional render guarded by a flag, never a deletion.
Changed
  • Hid "Explore" and "Marketplace" nav items — only Library and My Trips remain visible.
  • Library Explorer — hid Personal and Discovery tabs, only Global remains.
  • Trip overview — hid "Start Trip" (live on-trip companion); kept the Grey Board panel visible.
  • Day builder — hid "Optimize Route" (violated the product's own "warn, never auto-fix" principle) and "Suggest Accommodation."
  • Landing page — repointed all "Explore" CTAs to the working global library page instead of the now-hidden picker.

v0.3.0

Block Discovery Pipeline 1.1.0 → 1.2.0

Brings Iceland's library up to the same real-data standard as Germany's. Found along the way that Iceland's public library was 88% template-generated mock data approved into production by mistake, and that 0% of blocks in either country had real images — a silent merge bug plus a missing HTTP header were quietly zeroing out every discovery request. Fixes both, adds real image sourcing, and hardens the pipeline against two quota-wasting failure modes found by running it for real.

Added
  • Google Places Photos support, resolved to a servable image URL during discovery.
  • A name-based filter blocking image search for generic labels ("Viewpoint N," "Church") after these confidently returned unrelated photos.
  • A pre-enrichment cap per category, after one query type returned nearly 3,000 raw results against an 80-place ceiling.
  • A reusable backfill script attaching real images to already-approved blocks with none.
Fixed
  • The dedup path taken by most places never surfaced a resolved image to the merged record — any image found during discovery was silently discarded before import. Root cause of 0% image coverage.
  • The OSM fetcher was rejected on every request due to missing headers — zero OSM results ever made it into a pipeline run, invisibly.
  • Google Places quota exhaustion previously crashed the entire run rather than degrading gracefully. Both paths now continue without further calls to that source, falling back to Wikimedia.
discovery-pipeline.tsillustrative — quota exhaustion handling
try {
  const photo = await googlePlacesPhoto(candidate);
  return attachImage(candidate, photo);
} catch (err) {
  if (isQuotaExhausted(err)) {
    quotaExhausted = true; // stop calling this source for the rest of the run
    return attachImage(candidate, await wikimediaFallback(candidate));
  }
  throw err;
}

Illustrative — reconstructed from the description above to show the shape of the fix, not a copied diff.

Data
  • Removed 484 template-generated mock blocks approved into Iceland's live library by mistake.
  • Backfilled images: Germany 149/150 (99.3%), Iceland ~115/328 after removing 10 confirmed wrong matches.
  • Net effect: Iceland's live library grew from 65 real blocks to 328.

v0.2.0

Library Explorer UI — new · Region Assignment 1.0.0 → 1.1.0

Adds country/region-based browsing to the Global Library and extends discovery beyond its original Iceland-only scope, fixing two multi-country bugs uncovered while onboarding Germany as the platform's second fully-populated country (150 attractions across 8 regions).

Added
  • Country and region dropdowns on the global library page, replacing the old single-country filter.
  • Germany added as a supported country, targeting 6 states initially; bounding boxes added for all 16 so any discovered place resolves to an accurate region.
Fixed
  • Region resolution hardcoded a single country as fallback regardless of which was actually being processed — silently mislabeling every other country's places.
  • Country values stored an ISO code instead of the display name used everywhere else, silently splitting one country's data into two disconnected buckets.
  • The region-lookup query used a filter pattern the ORM's newer version rejects outright — broke the region endpoint for every country, not just new ones.
